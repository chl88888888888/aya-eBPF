# aya-test

Redis 是目前互联网行业部署最广泛的内存键值数据库，它的性能直接影响着现代互联网服务的用户体验，然而Redis 内置的监控工具 MONITOR（性能开销 >50%）、SLOWLOG（仅记录慢查询）和 INFO（仅提供平均值）效果很差，无法在不影响生产环境性能的前提下提供包括尾延迟在内的性能检测
eBPF（extended Berkeley Packet Filter）技术是Linux系统中的一个子模块，它提供了一种能在内核中安全运行沙箱化程序的接口，能使得开发人员据此构建零侵入、低开销、高精度的性能追踪系统，因此本项目基于纯 Rust 语言实现的 Aya eBPF 框架，设计并实现了一个覆盖延迟追踪、RESP 协议解析、CPU 火焰图生成和吞吐量统计的 Redis 性能追踪系统
本项目系统在 Linux 内核的 TCP 协议栈层面（tcp_recvmsg/tcp_sendmsg）插入了 fentry/fexit 探针，在纳秒精度上测量请求-响应的延迟，还采用了内核采集原始字节 + 用户态进行字节分析解析路径的架构，实现了任意 Redis 命令的动态识别与分类（准确率 100%），另外通过 perf_event 程序以默认 99Hz 频率(可调节)进行 CPU 栈采样，结合 goblin ELF 符号解析和 inferno 火焰图渲染，无需任何外部 profiler 即可生成交互式 SVG 火焰图，项目系统目前经 13 轮迭代演进，从单一原型逐步工程化为包含 11 个模块、支持 CLI 配置、持久化日志、自监控、吞吐量统计和客户端级 IP 追踪的完整性能追踪工具
实测数据表明，在 2 核、2 GB、Linux 7.0 的虚拟机上，单连接低负载下 eBPF 观测引入的吞吐量下降直接淹没于噪声数据（用户态进程自身 CPU 仅 ~2%），在高并发极限压测（C=100，27.7 万 RPS）下吞吐量下降约 11.2%，该值源于每秒约 80 万次探针触发和二阶段 RingBuf 推送的累积成本，典型生产负载下影响还会再降低，同时，系统成功捕获了 Redis 的尾延迟特征（P50≈2.43 μs, P99≈17.09 μs, P999≈43.71 μs），吞吐量统计与 redis-benchmark 自报值偏差 < 15%，并生成了清晰的命令级延迟分布、客户端级请求占比和 CPU 火焰图，最后，本文基于实验数据，从大键操作、进程调度抢占、持久化阻塞、内存碎片等七个维度系统分析了 Redis 尾延迟的成因
